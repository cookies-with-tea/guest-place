# @admin-panel/ui

Общий UI-кит для всех MFE проекта. Живые примеры — в Storybook (`pnpm --filter admin-docs storybook`, порт 6006).

## Когда `Ui*`, когда `<el-*>` напрямую

**Раздел 4 ROADMAP.md** просил явную политику — вот она, по факту кода, а не по привычке: низкое усыновление части компонентов кита (`UiButton` — 1 применение против 237 `<el-button>` в приложениях на момент аудита, `UiInput`/`UiSelect` — 0) оказалось не вопросом привычки разработчиков, а реальным разрывом в зрелости компонентов. Три разные ситуации:

### 1. Тонкие обёртки над `<el-*>` (`v-bind="$attrs"` + все слоты) — используй всегда

`UiSelect`, `UiTable`, `UiTableColumn`, `UiModal`. Это Element Plus без потери возможностей — только брендовые стили и, где есть, доп. функциональность (`UiTableColumn` добавляет сортировку/фильтр через `UiSortableHeader`, `UiModal` — дефолтный футер с Cancel/Confirm). Использовать `<el-select>`/ `<el-table>`/`<el-table-column>`/`<el-dialog>` напрямую в новом коде не надо.

### 2. Самостоятельные компоненты кита — используй, когда их возможностей хватает

`UiButton` (почищен — раньше ссылался на несуществующие CSS-переменные и не рендерил брендовые стили вообще, см. git-историю; теперь поддерживает `appearance`/`size`/`disabled`/`loading`), `UiFilterBar`, `UiGlassCard`, `UiRichTextField`, и новые виджеты раздела 1 ROADMAP (`UiStatCard`, `UiDonutProgress`, `UiAreaChart`, `UiSparkline`, `UiRankedList`).

`UiInput` — тоже в этой категории, но ограничен (`text`/`password`/`email`, без `clearable`, без prefix/suffix-иконок, без textarea-режима). Для простого текстового поля — используй. Если нужна функциональность, которой у него нет — `<el-input>` напрямую, это не ошибка, а осознанный выбор (дотягивать `UiInput` до паритета с `el-input` — отдельная, более крупная задача).

### 3. Всё остальное — `<el-*>` напрямую, это нормально

`el-form`/`el-form-item`, `el-tag`, `el-row`/`el-col` (уже фактический grid-стандарт проекта — 47+22 использования, отдельные `Container`/`Grid`/ `Stack` поверх него не нужны), `el-radio*`, `el-tooltip`, `el-tabs`, `el-dropdown*`, `el-switch`, `el-upload`, `el-date-picker` и т.д. — для них нет и не планируется `Ui*`-обёртки: Element Plus уже даёт нужную функциональность, обвязка добавила бы только лишний слой поддержки без пользы. Создавай `Ui*`-обёртку только когда накопится **подтверждённое кодом** (не гипотетическое) повторение кастомной вёрстки вокруг одного и того же `<el-*>` в 3+ местах — так появился `UiFilterBar`.

## Mobile-first

admin-panel — в основном desktop-ориентированный power-user инструмент (сложные таблицы, конструкторы схем/страниц). Адаптив — не по умолчанию для каждой страницы; делается точечно там, где экран должен быть удобен на узком окне (решается на уровне конкретной страницы, не всего кита).

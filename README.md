## Требования

Для локальной работы с проектом необходимы:
- **Node.js**: версии 22+ (рекомендуется согласно `.nvmrc`)
- **pnpm**: версии 9+ (`corepack enable && corepack use pnpm@9.0.6`)
- **Docker & Docker Compose**: для локального запуска PostgreSQL и Redis
- **Rust & Cargo** (1.75+): для запуска локального бэкенда (`server`)

## Быстрый старт и запуск для разработки

Чтобы запустить весь комплекс (бэкенд + админка) локально, выполните следующие шаги:

### Шаг 1. Запуск бэкенда и базы данных

Админка получает список активных микрофронтендов и данные через API бэкенда (`/api/v1/mfe/manifest`).

1. Перейдите в папку сервера:
   ```bash
   cd ../server
   ```
2. Создайте файл `.env` из примера:
   ```bash
   cp .env.example .env
   ```
3. Запустите контейнеры базы данных PostgreSQL и Redis:
   ```bash
   docker compose up -d db redis
   ```
4. Примените миграции базы данных (создаёт таблицы и сиды микрофронтендов):
   ```bash
   sqlx migrate run
   ```
5. Запустите сервер:
   ```bash
   cargo run
   ```
   *Сервер будет доступен по адресу: `http://localhost:8000`.*

---

### Шаг 2. Установка зависимостей админки

Вернитесь в директорию `admin-panel`:
```bash
cd ../admin-panel
```

1. Установите зависимости:
   ```bash
   pnpm install
   ```

2. Убедитесь, что в файле `.env` указан адрес бэкенда:
   ```bash
   cp .env.example .env
   ```
   Содержимое `.env`:
   ```env
   VITE_API_BASE=http://localhost:8000
   VITE_BASE_URL=http://localhost:8000
   ```

3. Выполните первоначальную сборку разделяемых пакетов:
   ```bash
   pnpm build:packages
   ```

---

### Шаг 3. Запуск админки (режимы работы)

Выберите подходящий сценарий:

#### Вариант А. Полноценная разработка (Рекомендуемый)

Микрофронтенды собираются и раздаются на предпросмотр-портах (`3001`–`3010`), а главное приложение `admin-shell` запускается с горячей перезагрузкой (HMR) на порту `4173`:

```bash
pnpm dev:all
```

*Что делает эта команда:*
1. Выполняет быструю сборку пакетов и приложений (`pnpm build`).
2. Запускает параллельно:
   - `preview:mf` — раздача скомпилированных `remoteEntry.js` микрофронтендов.
   - `dev:shell` — запуск хоста `admin-shell` в dev-режиме на `http://localhost:4173`.

> **Совет**: если вы вносите правки в конкретный микрофронтенд при работающем `dev:all`, пересоберите его в отдельном терминале: `pnpm --filter admin-statistics build`.

---

#### Вариант Б. Полный локальный Preview (Production-like)

Сборка и предпросмотр всей системы целиком без dev-серверов:

```bash
pnpm build
pnpm preview
```
Откройте браузер по адресу: `http://localhost:4173` (или `http://localhost:3000`).

---

#### Вариант В. Изолированная разработка одного микрофронтенда (Standalone Dev)

Если вам нужно разрабатывать конкретный микрофронтенд (например, `admin-statistics` или `admin-users`) с мгновенным HMR без запуска остальных модулей:

- Через интерактивное меню:
  ```bash
  pnpm dev:project
  ```
  *(выберите стрелками и пробелом нужный проект, нажмите Enter)*

- Или прямой командой:
  ```bash
  pnpm --filter admin-statistics dev
  ```
  Микрофронтенд откроется автономно на своём порту (например, `http://localhost:4174`).

---

### Шаг 4. Вход в систему (учётные данные)

Откройте в браузере `http://localhost:4173` (или порт, выведенный в консоли shell).

Данные суперпользователя по умолчанию:
- **Email**: `admin@example.com`
- **Пароль**: `admin`

После входа хост-приложение автоматически загрузит манифест с бэкенда и смонтирует все доступные разделы в боковое меню.

---

### Шаг 5. Запуск клиентского сайта (опционально)

Если требуется параллельно тестировать публичный сайт гостей:
```bash
cd ../client
pnpm install
pnpm dev
```
*Сайт будет доступен по адресу: `http://localhost:3000`.*

## Скрипты и команды

Все команды запускаются из корня `admin-panel/`:

### Разработка и предпросмотр

```bash
# Запуск shell в dev + всех MFE в preview (основной рабочий режим)
pnpm dev:all

# Быстрый запуск всех dev-серверов параллельно
pnpm dev:fast

# Запуск только хост-приложения
pnpm dev:shell

# Интерактивный запуск выбранных приложений
pnpm dev:project

# Запуск preview-серверов всех микрофронтендов
pnpm preview:mf

# Полный предпросмотр (все MFE + shell)
pnpm preview
```

### Сборка

```bash
# Полная сборка всех пакетов и приложений монорепозитория
pnpm build

# Сборка только разделяемых библиотек (@admin-panel/*)
pnpm build:packages

# Сборка только микрофронтендов и UI
pnpm build:mf

# Интерактивная сборка выбранного проекта
pnpm build:project

# Проверка размеров бандлов
pnpm check-size
```

### Тестирование

```bash
# Запуск всех unit-тестов
pnpm test

# Запуск тестов только для изменённых файлов (git status)
pnpm test:changes

# Запуск тестов с отчётом о покрытии кода (coverage)
pnpm test:coverage
```

### Проверка качества кода (Линтинг и форматирование)

```bash
# Проверка ESLint во всех проектах
pnpm eslint

# Автоисправление ошибок ESLint
pnpm eslint:fix

# Проверка стилей Stylelint
pnpm stylelint

# Автоисправление стилей Stylelint
pnpm stylelint:fix

# Проверка форматирования Prettier
pnpm prettier

# Автоформатирование всего проекта Prettier
pnpm prettier:fix

# Комплексный запуск всех проверок через Turborepo
pnpm lint

# Комплексное автоисправление через Turborepo
pnpm lint:fix

# Проверка согласованности версий зависимостей в монорепозитории
pnpm syncpack:lint
pnpm syncpack:format
```

### Storybook (Дизайн-система)

```bash
# Запуск локального Storybook для пакета UI
pnpm storybook

# Предпросмотр собранного Storybook
pnpm preview-storybook
```

### Создание нового микрофронтенда

В монорепозитории настроен генератор для создания новых микрофронтендов по стандарту проекта:

```bash
pnpm create:mf
```

Скрипт запросит название модуля, создаст структуру папок с архитектурой Feature-Sliced Design (FSD), настроит `vite.config.ts` с Module Federation и добавит необходимые зависимости.

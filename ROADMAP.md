# Guest Place — Roadmap

Три части проекта (`admin-panel`, `client`, `server`) с приоритетами:

- **admin-panel** — приоритет качества кода и UX. Основной рабочий инструмент.
- **client** — черновик, намеренно не дотянут, дорабатывается после admin-panel.
- **server** — должен работать и давать admin-panel нужные API; архитектурная
  чистота бэкенда вторична по сравнению с frontend-частями.

Обновляйте этот файл по ходу работы — вычёркивайте закрытые пункты, добавляйте
новые, если находите по пути ещё один источник проблем.

## 1. Редизайн admin-panel (приоритет)

Референсы — три скриншота в `admin-panel/docs/redesign-reference/`:
`master-x-admin-dashboard.webp`, `dashdark-x.webp`, `dotpress.png`. Перед
стартом каждого пункта — посмотреть референсы ещё раз, не работать по памяти.

Текущее состояние (проверено по коду, не предположение): primary-цвет —
Vue-зелёный `$gp-primary: #42b883` (`packages/ui/assets/styles/_variables.scss`),
accent — синий `#0284c7`/`#06b6d4` (`packages/ui/assets/styles/core/_tokens.scss`).
Дизайн — "glassmorphism" (полупрозрачные карточки, блюр), у всех трёх
референсов — сплошные непрозрачные карточки с мягкой тенью. Единственный
переиспользуемый card-компонент в `@admin-panel/ui` — `UiGlassCard`; готовых
KPI-карточки с трендом, donut/radial-прогресса, sparkline-виджета — нет,
каждое приложение сейчас верстает такое само (так было с `SparklineMetric.vue`
в `admin-orchestrator`, разобранным ранее). Графики в двух приложениях на двух
разных библиотеках: `admin-statistics` — ECharts (`vue-echarts`),
`admin-orchestrator` — сырой D3 для своих спарклайнов. Есть
`UiThemeBuilder`/`useThemeBuilder` — пользовательская рантайм-настройка
`--gp-primary`/блюра через localStorage, не трогает дефолты в SCSS.

1.1. [x] **Цветовая палитра** — сделано. `$gp-primary` в
   `_variables.scss`/`_tokens.scss`: `#42b883` → `#7c3aed` (светлая тема),
   `#a78bfa` (тёмная, ярче для контраста). `--accent-primary`/`--accent-hover`
   больше не отдельный синий — алиас на `--gp-primary`/`--gp-primary-hover`.
   Glassmorphism-токены (`--gp-bg-glass` и парные, `--gp-bg-surface`/
   `--gp-bg-element` в тёмной теме) заменены на solid-цвета вместо
   `rgba(...)`, `--gp-glass-blur: 0`. `styles-loader.ts`'s CRITICAL_CSS и
   `useThemeBuilder`'s `DEFAULT_ACCENT` обновлены тем же цветом (иначе FOUC
   и "Reset" темы на мгновение показывали бы старый зелёный). Проверено
   через `pnpm build` + `pnpm preview` в реальном федеративном шелле (dev
   mode не поддерживает module federation) — светлая и тёмная тема, живым
   браузером. ~20 файлов в admin-content/admin-orchestrator/admin-statistics
   с захардкоженным `#42b883` напрямую в своих графиках/конфигах — не
   трогал (не через CSS-переменную, часть может быть осознанным "success
   green"), кандидат на аудит вместе с 1.2's консолидацией графиков.
1.2. [x] **Виджеты в `@admin-panel/ui`** — сделано пять: `UiStatCard` (KPI
   с бейджем тренда ▲/▼ %), `UiDonutProgress` (кольцевой прогресс, значение
   по центру), `UiAreaChart` (line/area с градиентной заливкой,
   мульти-серия, легенда), `UiSparkline` (без осей, для карточек),
   `UiRankedList` (иконка/флаг + подпись + значение + прогресс-бар + тренд —
   "Installed by Country"/"Applications" на референсах). World-map с точками
   (DotPress — "Visitors Map") не делал — нужны гео-данные, отдельная,
   более тяжёлая задача.
   - Графики — на ECharts (`vue-echarts`), решение по единой библиотеке
     принято: `echarts`/`vue-echarts` помечены `external` в
     `packages/ui/vite.config.ts` (как `vue`/`pinia`/`element-plus`),
     потребляющее приложение ставит их сам (сделано для `admin-docs`, чтобы
     собрать Storybook-истории). `admin-orchestrator`'s D3-спарклайн на
     новый `UiSparkline` **ещё не перенесён** — сам виджет для этого готов,
     перенос — отдельный шаг.
   - Новый `packages/ui/src/lib/resolveCssColor.ts`: ECharts рисует в
     canvas и не резолвит `var(--x)` сам — composable читает значение через
     `getComputedStyle` и держит в курсе смены темы.
   - Два бага пойманы и исправлены через живой браузерный харнесс
     (Storybook): `UiSparkline` не регистрировал ECharts' `GridComponent` —
     без него график не рисовался вовсе (не визуально "пусто", а реальная
     ошибка `xAxis "0" not found` в консоли); `UiAreaChart`'s палитра по
     умолчанию использовала `var(--el-color-primary, ...)` для второй
     серии — в этом приложении `--el-color-primary` равен `--gp-primary`,
     так что все серии накладывались друг на друга одним цветом и
     выглядели как одна линия. Без браузерной проверки обе находки остались
     бы незамеченными при обычном код-ревью.
   - Storybook-истории на все пять (`apps/admin-docs/stories/`), проверены
     живым браузерным харнессом — рендерятся и реагируют на смену темы.
1.3. [x] **Layout** — сравнение с референсами показало, что структура

## 2. Открытое по тексту/контенту

- Улучшить UX самого SchemaBuilder: группировка/вложенность полей в canvas,
  переиспользуемые блоки полей между схемами (например общий SEO-блок сейчас
  либо копируется вручную в каждую схему, либо не предусмотрен).
- `client/app/pages/about`, `.../pagePlatforms` читают схемы `page_about`/
  `page_platforms` через `useCmsPage`, которых нет в БД — обе страницы
  гостям всегда показывают зашитый в код фолбэк, не CMS-контент. Поля там
  плоские (`hero_title`/`guest_features`/...), другой формы, чем у
  мигрированных структурированных `about`/`guests`/`platforms`
  (`opportunities`/`leadership`/`news`) — 1:1 не смэппить. Решать вместе с
  вёрсткой клиента (раздел 3), не раньше.

## 4. UI-унификация (по мере времени)

- Политика Element Plus vs `@admin-panel/ui`: сейчас большинство страниц
  используют `<el-*>` напрямую, минуя свой UI-кит — нужна явная политика,
  когда что уместно.
- Mobile-first аудит — решить, какие экраны admin-panel должны быть удобны на
  узких окнах (таблицы в `admin-media` и т.п.), какие осознанно остаются
  desktop-only power-user инструментами.
- `Container`/`Grid`/`Stack` layout-примитивы — если найдётся подтверждённое
  кодом повторение верстки (сейчас такого не было, `UiFilterBar` уже выделен).

## 5. CI / инфраструктура

- `make check-api-drift`/`make smoke-test` не подключены к GitHub Actions —
  у репозитория нестандартная структура (несколько веток одного GitHub-репо
  вместо единой монорепо-ветки), решение по событию/веткам — не чисто
  техническое, ждёт владельца продукта.
- `.github/workflows/ci.yml` в `admin-panel` закомментирован целиком —
  раскомментировать и включать джобы поэтапно, по одной.

# Roadmap развития Admin Panel & Guest Place

План и идеи для дальнейшего развития административной панели и всей экосистемы Guest Place.  
Все предложения ориентированы на **полностью локальную и self-hosted разработку** без привязки к сторонним облачным сервисам (AWS, S3-бакеты, облачные БД и т.д.).

---

## 🧭 Принципы развития

1. **Zero Cloud Lock-in**: вся функциональность работает автономно на локальной машине или собственном сервере (Docker, PostgreSQL, Redis, локальная файловая система).
2. **Модульность микрофронтендов**: каждая бизнес-область изолирована, но использует единую дизайн-систему (`@admin-panel/ui`) и библиотеку утилит (`@admin-panel/lib`).
3. **Developer Experience (DX)**: запуск всей экосистемы одной командой, быстрая локальная сборка, автогенерация типов из OpenAPI backend'а.
4. **Надёжность и производительность**: локальное кэширование, SSE/WebSocket для реактивных данных, целостность версий контента и переводов.

---

## 📌 Приоритетные направления (Roadmap)

### 1. Локальное медиа-хранилище и обработка (`admin-media`)

- [x] **Локальное чанковое хранилище (Resumable Uploads)**:
  - Поддержка догрузки больших файлов частями прямо на диск бэкенда с проверкой контрольной суммы (MD5/SHA256).
- [x] **Автоматическая генерация превью и WebP/AVIF на бэкенде**:
  - Генерация responsive-размеров (thumbnail, medium, large) средствами Rust (`image` crate) при загрузке изображения на локальный диск.
- [x] **EXIF & Metadata Stripping / Extraction**:
  - Извлечение габаритов, цветовой палитры и очистка чувствительных метаданных при локальном сохранении.
- [x] **Категории, теги и умный поиск по медиа**:
  - Локальная фильтрация по типам файлов, размерам, датам и тегам в интерфейсе `admin-media`.
- [x] Изменить заполнение контента переводов
  - Например, чтобы не писать "Привет, {span}мир{/span}" использовать редактор, который будет автоматически проставлять нужные теги и они будут попадать под перевод. Нужно учитывать вложенные теги. Также необходимо протестировать все кейсы переводов.

---

### 2. Headless CMS и Контент-конструктор (`admin-content`)

- [ ] **Визуальный блочный редактор (Block / Rich-Text Editor)**:
  - Внедрение компонентного редактора (на базе Tiptap или Editor.js) для создания гибких страниц сайта.
- [ ] **Интерактивный Schema Builder**:
  - Drag-and-drop конструктор полей для создания схем (`singleton`, `collection`) с валидацией типов (строки, числа, даты, ссылки на медиа).
- [ ] **Предпросмотр контента в реальном времени (Live Preview)**:
  - Режим Split-screen с `iframe`, отображающим клиентский сайт (`http://localhost:3000`) с мгновенным применением несохранённых черновиков через `postMessage`.
- [ ] **История версий и Diff-просмотр**:
  - Наглядное сравнение изменений между ревизиями контента (side-by-side diff) и откат к любой исторической версии одним кликом.

---

### 3. Локализация и переводы (`admin-translations`)

- [ ] **Импорт и экспорт переводов (JSON, CSV, PO)**:
  - Удобный импорт/экспорт для передачи текстов редакторам без прямого доступа к базе данных.
- [ ] **Детектор пропущенных ключей (Missing Keys Finder)**:
  - Сравнение дерева ключей между локалями (например, `ru` vs `en`) с подсветкой отсутствующих переводов.
- [ ] **Поиск неиспользуемых ключей в коде**:
  - Локальный CLI-скрипт сканирования фронтендов (`client` и `admin-panel`) на предмет устаревших ключей i18n.
- [ ] **Inline-редактирование и пакетные операции**:
  - Массовое редактирование ключей, фильтрация по пространствам имён (namespaces) и статусу заполненности.

---

### 4. Управление микрофронтендами и оркестратор (`admin-orchestrator`)

- [ ] **Health-check & Status Dashboard**:
  - Индикатор доступности каждого MFE (ping URL `remoteEntry.js`, замер latency, отображение версии и размера чанков).
- [ ] **Feature Flags на уровне микрофронтендов**:
  - Включение/отключение отдельных MFE и пунктов бокового меню без перезапуска сервера через интерфейс оркестратора (с сохранением состояния в PostgreSQL).
- [ ] **Динамический Fallback для упавших MFE**:
  - Полноценная заглушка «Сервис временно недоступен» с кнопкой повторной попытки загрузки модуля прямо внутри контейнера страницы в Shell.

---

### 5. Аналитика и мониторинг (`admin-statistics`)

- [ ] **Локальный сбор событий без сторонних трекеров**:
  - Приём внутренних событий перехода/кликов от клиентского сайта (`client`) через легковесный эндпоинт в Rust Axum с записью в PostgreSQL/Redis.
- [ ] **Когортный анализ и воронки конверсий**:
  - Расчёт когорт удержания (retention) и шагов воронки бронирования/регистрации гостя на базе SQL-агрегаций.
- [ ] **Экспорт отчётов в CSV/PDF**:
  - Локальная генерация отчётов по посещаемости, активности пользователей и удержанию.

---

### 6. Безопасность, RBAC и Аудит (`admin-users` & `server`)

- [ ] **Журнал аудита действий (Audit Log)**:
  - Фиксация всех критических операций (кто, когда, какое поле изменил, старое/новое значение, IP-адрес) с таблицей в PostgreSQL.
- [ ] **Двухфакторная аутентификация (2FA / TOTP)**:
  - Генерация QR-кода и проверка TOTP (Google Authenticator / Aegis) полностью локально на Rust сервере без внешних SMS-провайдеров.
- [ ] **Матрица прав доступа (Granular Permissions)**:
  - Визуальное управление правами с детализацией до уровня действий над сущностью (Create, Read, Update, Delete, Publish).

---

### 7. Real-Time и реактивность (Server-Sent Events / WebSockets)

- [ ] **SSE-уведомления для администраторов**:
  - Уведомления в реальном времени: регистрация нового гостя, загрузка нового медиафайла, системные события.
- [ ] **Блокировка одновременного редактирования (Entity Locking)**:
  - Механизм «Мягкой блокировки» через Redis: если один администратор редактирует статью или схему контента, другие видят предупреждение «Редактирует: Иван».

---

### 8. Инфраструктура и локальный DX (Developer Experience)

- [ ] **Единый скрипт локального запуска (Root dev orchestrator)**:
  - Команда в корне проекта (например, `pnpm dev:full` или Makefile), которая последовательно:
    1. Поднимает PostgreSQL и Redis через Docker Compose.
    2. Применяет миграции базы данных.
    3. Запускает бэкенд на Rust (`cargo run`).
    4. Запускает админку (`pnpm dev:all` или `pnpm dev`).
    5. Запускает сайт для гостей (`client`).
- [ ] **Генератор фикстур и тестовых данных (Seed generator)**:
  - Скрипт быстрого наполнения локальной базы правдоподобными данными: 50+ пользователей, медиатека, статьи, переводы, аналитические события за последние 30 дней.
- [ ] **Автоматическая синхронизация типов TypeScript из OpenAPI**:
  - Генерация TypeScript-типов из `server/openapi.json` прямо в `@admin-panel/lib` командой `pnpm generate:api`.
- [ ] **Автоматические локальные E2E тесты**:
  - Запуск Cypress/Playwright в headless-режиме против локального окружения с мок-авторизацией.

## 🗓️ Рекомендуемый порядок реализации (Фазы)

| Фаза | Фокус | Ключевой результат |
| --- | --- | --- |
| **Фаза 1: DX & Автоматизация запуска** | Корень, Docker, Скрипты | Единый запуск всего стека (`docker compose`, `cargo run`, `pnpm dev:all`), синхронизация типов OpenAPI |
| **Фаза 2: Контент & Медиа** | `admin-content`, `admin-media` | Блочный редактор страниц, автоматические WebP превью на диске, Live Preview |
| **Фаза 3: Переводы & Управление MFE** | `admin-translations`, `admin-orchestrator` | Импорт/экспорт словарей, health-check микрофронтендов, graceful fallback |
| **Фаза 4: Аудит & Безопасность** | `admin-users`, `server` | Локальный Audit Log в БД, мягкая блокировка редактирования в Redis, TOTP 2FA |
| **Фаза 5: Локальная аналитика** | `admin-statistics` | Внутренний трекер событий без сторонних SDK, экспорт отчётов |
